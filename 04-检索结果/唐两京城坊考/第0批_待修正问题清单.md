## 问题 2：关系表方位数据严重缺失

**现状**：Layer 2 只提取了约 140 条（ADJACENT_TO + NEAR），NORTH_OF / EAST_OF / WEST_OF / SOUTH_OF 几乎没有。

**原因**：原文方位表述（如"甘露殿北為延嘉殿"、"承天門東長樂門"、"次東延政門"）为古典汉语，正则模式覆盖率不足。

**拟解决**：重写 Layer 2 提取逻辑，扩展以下模式——

- "X北為Y" / "X南為Y" / "X東為Y" / "X西為Y"
- "X門東Y門" / "X門西Y門"（已部分覆盖）
- "次東Y" / "次西Y"
- "X之北有Y" / "X之東有Y"
- 同一 parent_area 下实体的方位描述互参

**预计**：从 ~140 条补充到 300+ 条。

## 问题 3：relation_label 和 note 格式不符规范

**现状**：
- relation_label 用的是通用标签（"位于…内"、"相邻"），未描述具体关系
- note 直接粘贴了原文 evidence，不是关系描述

**规范要求**：
- relation_label 应为描述性短语，如"大明宫正南正门"、"承天门东侧相邻"
- note 应为自然语言描述两实体之间的关系，如"丹鳳門是大明宮正南門，位於宮城南壁正中"

**拟解决**：重写关系表生成逻辑，为每条关系自动生成描述性 label 和 note。

## 问题 4：实体表 description 字段应改为描述性文字，新增原文字段

**现状**：description 直接照录古文原文（繁体），可读性差，不利于前端展示。

**用户决策**：在实体表新增一个字段存放原文，description 改为描述性文字。

**拟方案**：

| 字段 | 内容 | 示例（丹鳳門） |
|------|------|-------------|
| description | 简洁的现代中文描述 | 大明宫正南门，位于宫城南壁正中，门上有楼 |
| description_quote（新增） | 原文直接引用（繁体） | 正南丹鳳門，〈隋開皇二年作…〉 |

- description_quote 保留溯源功能，对应史料片段表中的原文
- description 用于前端展示，可读性更好
- 通过 source_key 和 chunk_key 实现双重溯源

**影响范围**：539 个实体的 description 需全部重写（可用 AI 从原文自动生成现代中文描述）。
