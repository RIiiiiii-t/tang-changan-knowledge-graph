## 二、各轮审查要点与决策记录

### 第 1 轮：v1 → v2（用户首次审核）

**用户发现 3 个问题：**

1. **description 与原文不对应**
   - 问题：v1 的 description 字段是我改写/概述的，不是原文
   - 决策：全部改为原文直接引用，保留繁体中文，不做任何改写
   - 执行：v2 起所有 description_quote 字段均为原文逐句照录

2. **截断段落处理**
   - 问题：v1 对长段落做了截断，用户希望全文通读不遗漏
   - 决策：不截断，每个实体的 description 取完整原文句段
   - 执行：v2 起 description_quote 保留完整上下文

3. **提取不完整**
   - 问题：v1 只取了 27 个代表性实体，大量官署、殿宇、亭台等被遗漏
   - 决策：全量提取，凡文献中出现的命名实体全部录入
   - 执行：v2 从 27 个扩展到 539 个，使用 3 个并行子任务分别处理宮城、皇城、大明宮/興慶宮/三苑三大板块

### 第 2 轮：v2 → v3（用户二次审核）

**用户发现 1 个问题：**

4. **城门与殿门混淆**
   - 问题：城门（宫城/皇城外墙门）和殿门（建筑内部门，如承恩殿门）混在同一个类别里
   - 用户原话："先别改，是不是城门和殿门混在一起了"
   - 决策：分为两类——
     - **城门**（Gate）：宫城、皇城、禁苑、大明宫、兴庆宫等建筑群的外围门，共 52 个
     - **内门**（Building，category="内门"）：各殿、阁、楼等建筑内部的门，共 92 个，entity_type 从 Gate 改为 Building
   - 执行：编写 `reclassify_gates.py`，通过 parent_area 和命名规则自动分类

### 第 3 轮：v3 全面类别审计（用户要求）

**用户要求**："其他类别也看一下，有没有类似的混淆问题，如果有，先不要修改，报告给我。此外，你的宫殿区和殿宇是怎么分类的，一部分名为 xx 宫的建筑应该放到殿宇类吧。回答问题，先不要修改。以后每一步修改都要和我确认。"

**关键原则确立**：此后每一步修改必须经用户确认后方可执行。

**审计结果报告了 6 类问题：**

| # | 问题 | 涉及实体数 |
|---|------|-----------|
| 1 | 宫殿区中混入了"宫名殿宇"（名为xx宮但实为单体建筑） | 10 个 |
| 2 | 城门中混入了内门（應天門等皇城内部殿门） | 5 个 |
| 3 | 院类别混杂（有官署性质的坊、有园林、有军事院落） | 18 个需拆分 |
| 4 | 其他类别过杂（含地理地貌、桥梁、寺庙等） | ~20 个需拆子类 |
| 5 | 寺庙分散在其他中 | 4 个 |
| 6 | 人物遗漏（隋文帝、高熲在序/卷一中明确出现但未提取） | 2 个 |

**另发现**：通化門觀归在楼阁类不妥（它是一个城门附属的观楼，非独立楼阁）。

## 四、已确立的工作原则

以下原则在审查过程中逐步确立，后续批次应持续遵循：

1. **description 必须原文照录**：繁体中文，不改写、不概述、不截断
2. **全量提取**：凡文献中出现的命名实体全部录入，不做取舍
3. **分类必须准确**：城门（外围门/Gate）与内门（殿门/Building）严格区分；宫殿区（大型建筑群）与殿宇（单体宫名建筑）严格区分
4. **每步修改必须经用户确认**：先报告问题和方案，用户确认后再执行
5. **仅改类别不删条目**：除非明确为非唐代实体（如汉代旧宫），否则不删除
6. **不好归类的放其他**：宁可保守分类，不强行归入不合适的类别
