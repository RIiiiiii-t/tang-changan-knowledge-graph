## 一、工作总览

### 目标

通过逐份资料的全文逐段通读，尽可能全面、详细地从可靠史料中提取唐长安城的实体、关系和史料摘录，形成可演示、可搜索、可供 AI 问答的知识图谱数据库。

### 核心原则

- **逐段通读，不跳段**：每一段都完整阅读
- **全量登记，不遗漏**：不仅提取主体文本中的关系，还要提取注解（〈〉）中的人物关联、历史事件、名称变更
- **来源先行**：每一条数据必须有可追溯的来源
- **每步确认**：每一步修改必须经用户确认后方可执行
- **分批审核**：每完成一批即交付审核，确认后写入 Excel

### 数据流

```
用户提供 epub/PDF
       ↓
AI 逐段通读，全量提取（方案 A：AI 直接读原文）
       ↓
AI 生成本批审核表（实体 + 关系 + 史料片段）
       ↓
用户逐条审核：✓ 通过 / ✗ 修改 / – 删除
       ↓
AI 写入 Excel 模板（含 evidence_quote 等新增列）
       ↓
用户运行一键导入脚本 → 后端 → 前端
```

## 二、关系提取方法（方案 A）

### 方法说明

AI 直接阅读原始文言文，逐段理解语义后手写所有关系。不使用 LLM API 辅助，不使用纯正则匹配。

### 与旧方法的区别

| 对比项 | 旧方法（3层自动提取） | 新方法（方案 A） |
|--------|---------------------|-----------------|
| 提取方式 | 正则模式 + 结构化字段映射 | AI 直接读原文理解语义 |
| 覆盖范围 | 主体文本为主 | 主体文本 + 注解（〈〉） |
| 关系表 | 在旧数据基础上修补 | 从头重写 |
| 史料片段 | 未单独提取 | 每条典故独立记录 |

### 提取步骤

1. **文本分块**：按自然段落切分，每块约 1000-2000 字
2. **AI 阅读提取**：逐块阅读，识别所有实体间关系
3. **entity_key 匹配**：与实体表交叉验证，确保两端实体存在
4. **去重**：同一对实体的重复关系合并
5. **生成审核表**：按审核表 v3 格式输出
6. **用户审核**：逐条确认
7. **写入 Excel**

### 每段文本必须提取的关系

1. **主体文本**：空间归属（LOCATED_IN）、方位（EAST_OF 等）、邻接（ADJACENT_TO/NEAR）、正对（FACING）
2. **注解（〈〉）**：人物关联（ASSOCIATED_WITH）、历史事件（INVOLVED）、名称变更（记入 name_rename_history）
3. **史料典故**：每条独立记录到史料片段表

## 三、关系类型体系（13 类）

| 代码 | 中文 | 适用情况 |
|------|------|----------|
| LOCATED_IN | 位于…内 | 建筑位于区域内 |
| LOCATED_ALONG | 位于…沿线 | 位于街道沿线或一侧 |
| EAST_OF | 位于…东侧 | 明确东西方位 |
| WEST_OF | 位于…西侧 | 明确东西方位 |
| SOUTH_OF | 位于…南侧 | 明确南北方位 |
| NORTH_OF | 位于…北侧 | 明确南北方位 |
| NORTHEAST_OF | 位于…东北 | 复合方位 |
| ADJACENT_TO | 相邻 | 直接相邻 |
| NEAR | 靠近 | 空间接近但非直接相邻 |
| FACING | 正对 | 南北/东西正对 |
| CONNECTS_TO | 连接 | 街道与城门、区域的连接 |
| ASSOCIATED_WITH | 相关 | 人物与地点、建筑的关联 |
| INVOLVED | 涉及 | 事件涉及建筑、地点或人物 |

## 四、Excel 表结构

### 实体表（13 列）

entity_key, name, entity_type, aliases, category, period, description, location, start_year, end_year, source_key, confidence, **description_quote**

- name：简体
- aliases：简体
- description：简体白话文
- description_quote：繁体原文（新增列 13）

### 关系表（11 列）

relation_key, source_key, target_key, relation_type, relation_label, evidence_source_key, confidence, start_date, end_date, note, **evidence_quote**

- relation_label：简体白话文，包含所有可获取的信息
- note：简体白话文描述
- evidence_quote：繁体原文，尽可能完整引用（新增列 11）

### 史料片段（8 列）

chunk_key, source_key, content, chapter, volume, page, confidence, **note**

- content：繁体原文，直接写原文不加书名前缀
- note：简体白话文描述（新增列 8）

### 来源表（9 列）、填写说明、代码对照

不变。

## 七、质量规则

1. **编号唯一**：同一编号不能重复
2. **来源先行**：source_key / evidence_source_key 必须指向已存在的来源
3. **关系两端存在**：source_key 和 target_key 必须指向实体表中已有的实体
4. **置信度**：原文直述 ≥ 0.90，推理 0.75–0.85，存疑 ≤ 0.6
5. **争议保留**：不同资料说法矛盾时保留不同来源，notes 中说明
6. **字体规范**：除原文字段外全部使用简体字
7. **每步确认**：每一步修改必须经用户确认后方可执行
